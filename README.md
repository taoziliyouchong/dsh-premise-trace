# dsh-premise-trace —— 前提追溯

作用：一件事正在变化时，回望它怎么变成现在这样、说清现在靠什么成立、判断下一步会变成什么。

- **回望过去**：它从哪个状态转过来，中间哪几项变了
- **看清现状**：这个状态靠什么成立
- **往后**：下一步会变成什么，还有没有别的落点

## 怎么判

一个状态靠几项成立条件同时成立；条件变了状态未必变；条件失效且没有第二条路，状态才不成立。

四道判定，按顺序过：

| 判定 | 问什么 |
|---|---|
| 必要 | 撤掉它，状态还成立吗 |
| 独立 | 撤掉后剩下的是「另一种可描述的状态」，还是状态不存在／环境不存在 |
| 关键 | 塌了有没有第二条路补位 |
| 级联 | 撤掉会不会连带几项一起失效 |

七步：定状态 → 列候选 → 筛项 → 分内外 → 递归 → 交换 → 读变化。两态时多看一步补项回炉，直到两张表都不再增项。

## 三种交付

- **解释现状**：一张成立条件表，逐条标关键判定；表后一句「哪项现在在变、往哪变」。
- **解释转变**：A、B 两张表，加一段转化的原因与过程。
- **判断走向**：异动清单，加两三个可能（B 大概率，另有 C、D），每个跟一句「哪条条件怎么变才走到它」。

## 安装

```sh
dsh plugin --profile <profile> add github:taoziliyouchong/dsh-premise-trace
```

装完重启 DSH。技能名 `premise-trace`，出现在技能目录里；说「用前提追溯分析：……」，或直接问「它靠什么成立」「它下一步会变成什么」即可唤起。

本包没有工具、命令、路由与浏览器界面，装上前后唯一的区别是技能目录多一项。

## 包内容

| 文件 | 作用 |
|---|---|
| `index.js` | 向技能服务注册 `premise-trace`（bundled，档位 600） |
| `invariant.js` | 组合用的伴随插件 |
| `cordis.patch.yml` | 组合声明：`dsh plugin add` 靠这一行把插件接进层栈 |
| `assets/premise-trace.md` | 方法正文（技能加载时读取全文） |
| `scripts/smoke.mjs` | 本机冒烟：结构、组合声明、注册、正文可读 |

## 兼容

`engines.dsh` 声明 `>=0.2.1-0`（0.2.1-alpha.3、0.2.2-rc.1 实际运行验证）；更高版本未验证。

## 维护

```sh
npm run check    # 语法
npm run smoke    # 结构 / 组合声明 / 注册 / 正文可读
```

改方法正文只动 `assets/premise-trace.md`，改注册动 `index.js`；改完重启 DSH 生效。
